## 2. Product vision

NAQL AI is a national AI-powered logistics and international trade platform.

Tagline: PLAN — PREDICT — OPTIMIZE.

It connects importers, exporters, freight forwarders, carriers, customs professionals, logistics providers, enterprises, and authorized government stakeholders.

The platform should support:
- Shipment planning and route comparison.
- Freight quotation requests and provider offers.
- Estimated landed-cost calculations with transparent cost breakdowns.
- Shipment booking workflows and tracking timelines.
- Document management and AI-assisted document validation.
- HS code research assistance with appropriate uncertainty warnings.
- Delay risk estimation and shipment exception management.
- AI logistics copilot.
- Ports, routes, and logistics facilities map.
- Notifications, analytics, and operational dashboards.
- Carbon-emissions estimates where sufficient data exists.
- Future IoT tracking integrations.

Prioritize a functional, coherent, integrated system over disconnected feature demonstrations.

## 3. Required technology architecture

Use a modular monorepo with pnpm and Turborepo, subject to compatibility checks.

Frontend:
- Next.js with App Router.
- TypeScript with strict mode.
- Tailwind CSS.
- shadcn/ui and Radix UI where appropriate.
- Lucide icons.
- React Hook Form and Zod for form validation.
- TanStack Query for server-state management where useful.
- MapLibre GL JS with OpenStreetMap-compatible map services.
- ECharts for dashboards and analytics.

Backend:
- Node.js and TypeScript.
- Fastify.
- Zod request and response validation.
- Prisma ORM.
- PostgreSQL with PostGIS.
- Redis and BullMQ for background jobs when available.
- S3-compatible object storage behind an abstraction.
- REST APIs with versioning and OpenAPI documentation.

AI service:
- Python and FastAPI.
- Pydantic schemas.
- Provider-independent LLM integration.
- Document extraction and validation interfaces.
- Retrieval-augmented generation architecture.
- Shipment delay prediction interfaces.
- Model evaluation and confidence reporting.

Use a modular monolith with clear domain boundaries and event-driven integration where useful. Do not introduce microservices, Kafka, Kubernetes, or complex infrastructure without a demonstrated need.

The application must remain practical to develop on a Windows computer with limited resources. Avoid requiring Docker for basic local development. Provide native setup instructions and optional infrastructure profiles.

Check package compatibility and current stable APIs before selecting versions.

Build a working foundation for:

- Extracted-field schemas for commercial invoices, packing lists, and bills of lading.
- Cross-document consistency checks.
- Missing-field and discrepancy reports.

## 8. Database and API standards

- Use explicit relational models, indexes, unique constraints, and appropriate foreign keys.
- Use decimal-safe representations for money.
- Store currency codes and distinguish original amounts from converted amounts.
- Store timestamps consistently and present them in the user's appropriate timezone.
- Model shipment status transitions explicitly.
- Add pagination and filtering to collection endpoints.
- Generate OpenAPI documentation.
- Use consistent error responses and request IDs.
- Add health checks and structured logging.
- Keep secrets in environment variables.
- Use database migrations rather than undocumented manual schema changes.
- Seed only clearly identified development and demonstration data.

## 9. Security and quality

Implement an appropriate baseline for:
- Password hashing and secure session handling.
- Role-based and organization-scoped access control.
- Request validation and rate limiting.
- Secure file-upload validation.
- Protection against cross-tenant data access.
- Audit logging for important actions.
- Safe error messages and secret redaction.
- Tests for authentication, permissions, shipment workflows, and cost calculations.

Choose authentication libraries based on current compatibility and security guidance. Do not implement cryptographic primitives yourself.
